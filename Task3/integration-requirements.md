# Умный дом

добавляем smart-home-adapter для работы с партнёром. Собственник пользуется тем же мобильным приложением.

[Контекст](c4-context.drawio) · [Контейнеры](c4-containers.drawio) · [Исходная схема](PropDevelopment-original.drawio.xml)

## Как работает

пользователь входит через Keycloak. Приложение отправляет запрос в tenant-core-app, тот проверяет токен и доступ к квартире. Затем adapter вызывает API партнёра и возвращает результат.

через эту связь можно открыть домофон или шлагбаум, добавить лицо или номер машины в список доступа. Автоматическое распознавание выполняется на стороне партнёра. ID устройств и права храним в tenant-core-db, действия записываем в логи tenant-core-app.

## Требования

| что | решение |
|---|---|
| вход пользователя | OpenID Connect, Authorization Code + PKCE через существующий Keycloak |
| доступ к устройству | tenant-core-app проверяет владельца, дом и УК; чужое устройство открывать нельзя |
| связь с партнёром | REST по HTTPS, служебный токен OAuth 2.0 Client Credentials |
| права партнёра | отдельные разрешения на просмотр, открытие и изменение доступа |
| персональные данные | передавать только нужные поля, не открывать партнёру CRM и БД |
| биометрия | отдельное согласие, удаление при отзыве; у нас только ID профиля |
| хранение | согласовать с партнёром сроки хранения и удаления данных |
| ошибки | при таймауте показывать ошибку; повтор одной команды не должен выполнять её дважды |

токены и биометрию не пишем в логи и не выгружаем в DWH.

на полной схеме сохранены существующие системы и связи. В исходном XML были дубли у бухгалтерии: оставлен accountant-service-1, его БД подписана accountant-db. Подписи AD уточнены по связям.
